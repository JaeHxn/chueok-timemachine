## 3. OG·트위터 카드 메타태그

| 항목 | 내용 | 출처 |
|---|---|---|

| 이미지 | 1200×630(1.91:1) 권장이 일반적, 절대 URL·HTTPS | 페이스북 공유 가이드 [미확인] |
| 트위터 카드 | `twitter:card`=`summary_large_image` (없으면 OG로 대체) | https://developer.x.com/en/docs/x-for-websites/cards/overview/markup [미확인] |
| 카카오 OG 캐시 | 카카오 디벨로퍼스 [도구] > 공유 디버거(카카오톡 URL 메타정보 관리)에서 URL 조회 → 캐시 초기화. 같은 경로의 이미지는 초기화되지 않을 수 있어 **이미지 URL을 바꾸는 것이 확실**(버전 쿼리 등) | https://developers.kakao.com/docs/ko/tool/common , 이미지 캐시 사례: https://devtalk.kakao.com/t/og/147109 (커뮤니티 답변) |

예시:
```html
<meta property="og:title" content="1994년 7월 — 추억 아카이브">
<meta property="og:description" content="그해 여름 유행했던 것들">
<meta property="og:image" content="https://example.com/og/1994-07.png?v=3">
<meta property="og:url" content="https://example.com/1994/07">
<meta name="twitter:card" content="summary_large_image">
```

## 4. SPA(React)에서 크롤러가 OG를 보게 하는 방법

카카오·페이스북·X 크롤러는 JS를 실행하지 않는다고 보고 설계해야 한다(클라이언트에서 `document.head`를 바꾸는 방식은 미리보기에 반영 안 됨). [추측: 크롤러별 JS 실행 여부는 공식 문서로 확인하지 못함 — 안전하게 "실행 안 함" 가정]

| 방식 | 내용 | 장단점 |
|---|---|---|
| 빌드 시 프리렌더 | 연도·월 페이지처럼 개수가 정해진 경로는 빌드 때 경로별 HTML(메타태그 포함) 생성 | 가장 단순·빠름. 커뮤니티 글처럼 계속 늘어나는 경로엔 부적합 |
| Cloudflare Pages Functions + HTMLRewriter | 요청 시 Function이 `env.ASSETS.fetch()`로 SPA의 index.html을 받아 HTMLRewriter로 `<head>` 메타태그만 경로별로 바꿔 응답 | 동적 글에 적합, SPA 구조 유지. 요청당 Functions 사용량 발생 |
| 전체 SSR 프레임워크 | Next.js/Remix 등 | 기존 SPA면 전환 비용 큼 |

출처: Cloudflare Pages Functions https://developers.cloudflare.com/pages/functions/ , HTMLRewriter https://developers.cloudflare.com/workers/runtime-apis/html-rewriter/ [미확인: 이번에 미열람]

생성한 이미지는 캐시(Cache API/R2)에 두고, 내용이 바뀌면 URL의 버전 값을 바꿔 카카오 이미지 캐시 문제를 피한다.

## 6. 개인정보 주의

| 항목 | 권장 |
|---|---|
| 카드 이미지·OG 설명에 들어가는 내용 | 커뮤니티 글은 제목·짧은 발췌만, 닉네임 노출은 작성자 설정(기본 비노출 권장). 실명·연락처·얼굴 사진 자동 삽입 금지 |
| 비공개·삭제된 글 | 비공개 글은 OG에 일반 문구만 내보내고, 삭제 시 OG 이미지도 지움. 단 이미 카카오·페이스북 등에 캐시된 미리보기는 즉시 사라지지 않음(카카오 서버 업로드 이미지는 최대 100일 보관 [확인]) → 공유 전 "외부에 미리보기가 남을 수 있음" 안내 |
| 타인 글 공유 | 공유 링크는 원문 권한을 그대로 따르게(로그인 필요한 글은 미리보기에 내용 노출 금지) |
| 추적 파라미터 | UTM 정도만, 사용자 ID를 공유 URL에 넣지 않음 |
| 법령 | 개인정보 보호법(공개 범위·삭제 요청 처리)에 맞춰 처리방침에 "공유 시 노출 항목" 명시 [제안] |

## 추천 구현 방식

1. **공유 버튼 하나 + 시트**: 모바일에서 `navigator.canShare`가 되면 Web Share API(기기 공유 시트 → 인스타·카톡 등 앱 선택)를 우선, 안 되면 채널별 버튼(카카오톡·X·페이스북·네이버·링크 복사)을 보여 준다.
2. **카카오톡**: Kakao JS SDK `sendDefault`(피드 템플릿, 제목·설명·이미지·링크 직접 지정)를 기본으로. 도메인 등록 필수, 쿼터는 콘솔에서 확인.
3. **인스타그램**: 공식 웹 공유가 없으므로 "카드 이미지 저장" + 모바일 파일 공유(Web Share level 2) + 링크 복사.
4. **네이버 블로그**: `share.naver.com` URL은 공식 문서 미확인 → 직접 동작 테스트 후 채택, 실패 시 링크 복사.
5. **OG**: 연도·월·아이템 페이지는 빌드 프리렌더, 커뮤니티 글은 Cloudflare Pages Functions + HTMLRewriter로 경로별 메타태그 주입.
6. **OG 이미지**: 정적 페이지는 빌드 시 생성, 커뮤니티 글은 Workers에서 satori 계열로 생성 후 캐시, URL에 버전 값.
7. **개인정보**: 닉네임 기본 비노출, 비공개 글은 일반 미리보기, 삭제 후에도 외부 캐시가 남을 수 있음을 안내.
