## 1. 공유 흐름 명세

### 1.1 공통 원칙
1. 공유 대상은 세 종류다: **연·월 페이지**, **아이템 페이지**, **커뮤니티 글**. 모두 `/1997/11`, `/item/<id>`, `/post/<id>` 같은 고유 주소가 있어야 한다 [확정, §4.3].
2. 공유 링크는 3D 연출 없이 바로 그 페이지가 열린다(AC-03). 공유 링크 안에 사용자 ID를 넣지 않는다. 추적은 `utm_source`·`utm_medium`까지만 [조사 §6].
3. 공유 카드(OG 이미지)·공유 문구에는 **닉네임·아바타·사용자 사진을 기본으로 넣지 않는다** [확정, §4.7 ⑤].
4. AI 재현 아이템은 공유 카드에도 `AI 사료 복원` 표시가 따라간다(§5.5, AC-08의 공유판). 카드 이미지와 설명 문구 둘 다에 넣는다.
5. 비공개·삭제·신고 숨김 글은 공유 버튼을 숨기고, 이미 받은 링크는 일반 문구 미리보기로 바꾼다(§2.4).

### 1.2 공유 버튼 위치·동작 (화면별)

| 화면 | 버튼 위치 | 공유 카드 내용 | 공유 문구(text) | 비고 |
|---|---|---|---|---|
| 연도 페이지 `/1997` | 상단 HUD 우측(검색 옆)과 페이지 하단 반복 | 연도 큰 글씨 + 시대 테마 이름("사이버 펑크") + 대표 아이템 3개 텍스트 + 사이트명 | `1997년, 이런 게 유행이었어요 — 추억 타임머신` | 월 단위 콘텐츠가 부족하면 연도 카드만 제공 |
| 월 페이지 `/1997/11` | HUD 우측 + 카드 목록 위 | `1997.11` + 대표 아이템 3개(제목만) + 이 달 추억 글 수 | `1997년 11월, 다마고치·삐삐·IMF… 기억나세요?` (예시, 실제 아이템은 데이터) | "이 달 N건의 추억" 숫자는 공개 글 수만 |
| 아이템 `/item/<id>` | 제목 옆(갤러리 아래 말고 제목 줄에 붙임) | 제목 + 연월(정확도 반영) + 대표 이미지(§1.5 조건 충족 시) 아니면 텍스트 카드 + 출처 이름 + AI 배지 | `{제목} ({연월}) — 추억 타임머신` | "나도 기억나!" CTA와 가까이 두지 않는다(실수 클릭 방지) |
| 커뮤니티 글 `/post/<id>` | 글 헤더 우측 + 댓글 위 | 글 제목 + 본문 발췌(약 100자) + 연월 + 시대 배경색. 사진·닉네임 없음 | `"{글 제목}" — {연월}의 추억` | 작성자가 "카드에 내 사진 사용"을 켠 경우만 사진(§1.5) |
| 전체 피드·검색·홈 | 공유 버튼 없음(또는 사이트 전체 공유만) | 사이트 공통 카드 | `연도·월별로 한국 추억을 여행해요` | 개별 글 공유는 글 페이지에서 |

### 1.3 공유 시트 동작 (웹 공유 시트 → 채널별 대체)

[제안] 설계서 §4.7 ①("Web Share를 먼저, 안 되면 채널 버튼")을 아래처럼 보완한다. Web Share를 바로 호출하면 시스템 공유 시트가 열려서 **카카오 카드·인스타 이미지 저장** 같은 이 사이트 고유 선택지를 보여 줄 자리가 없어진다. 그래서 공유 버튼은 항상 **자체 시트**를 열고, 그 안에 "기기 공유(더보기)"를 한 칸으로 둔다.
- 대안 A(위 제안): 자체 시트 → 시트 안 "기기 공유"가 `navigator.share` 호출.
- 대안 B(설계서 원안): 모바일은 `navigator.share` 즉시 호출, 실패 시 자체 시트. 구현이 단순하지만 카카오 카드·이미지 저장 노출이 약하다. **[미정] 선택 필요.**

**시트 구성 (A안)**
- 모바일: 하단 시트(바텀시트). 데스크톱: 버튼 아래 팝오버. 닫기 버튼 + Esc + 바깥 클릭.
- 순서 [제안]: ① 카카오톡 ② 인스타그램(카드 이미지) ③ 링크 복사 ④ 네이버 블로그 ⑤ X ⑥ 페이스북 ⑦ 기기 공유(지원 시에만 표시).
- 시트 맨 위에 공유될 카드 미리보기(작게)와 제목 한 줄을 보여 준다 — 무엇이 나가는지 사용자가 보게 한다.
- 터치 영역 44px 이상, 아이콘 단독 금지(글자 라벨 병기).

**채널별 동작**

| 채널 | 동작 | 폴백 |
|---|---|---|
| 기기 공유 | `navigator.share({title, text, url})`. 사용자 클릭 안에서 호출. 지원 안 하면 이 칸을 아예 숨김. 사용자가 시트를 닫으면 `AbortError`가 나는데 **오류 표시 없이 무시** | 숨김 → 나머지 채널 사용 |
| 카카오톡 | §1.6 | SDK 로드·초기화 실패 시 칸 숨김, 링크 복사 권유 |
| 인스타그램 | §1.4 흐름 | 아래 §1.4 단계별 폴백 |
| 링크 복사 | `navigator.clipboard.writeText`(HTTPS·클릭 필요). 성공 토스트 "링크를 복사했어요" | 클립보드 접근 불가 시 선택된 입력창에 URL을 보여 주고 수동 복사 안내 |
| 네이버 블로그 | `https://share.naver.com/web/shareView?url=…&title=…` 새 창 [조사: 공식 문서 못 찾음 → **[확인 필요]** 출시 전 실제 동작 테스트 후 채택] | 동작 안 하면 이 칸을 빼고 "링크 복사"만 |
| X | `https://x.com/intent/post?text=…&url=…` [조사 §1, **[확인 필요]**] | 링크 복사 |
| 페이스북 | `https://www.facebook.com/sharer/sharer.php?u=…` [조사 §1, **[확인 필요]**] | 링크 복사 |

모든 외부 인텐트 링크는 `rel="noopener noreferrer"`로 새 창에 연다. 공유 URL에는 `utm_source={채널}&utm_medium=share`만 붙인다.

**환경별 주의 [전부 [확인 필요] — 실기기 테스트 항목]**
- 카카오톡·인스타그램·네이버 앱 안의 **인앱 브라우저**에서는 `navigator.share`·클립보드·다운로드가 막히거나 다르게 동작할 수 있다. 인앱이면 "다른 브라우저로 열기" 안내 + 링크 복사만 보여 주는 방안을 테스트로 결정한다.
- 데스크톱 Firefox는 Web Share 미지원(caniuse, 조사 §2). 시트의 "기기 공유"가 사라지는 정상 경로로 처리한다.
- 파일 공유는 `navigator.canShare({files})`가 true일 때만 "이미지로 공유"를 보여 준다.

### 1.4 인스타그램용 이미지 저장 흐름

전제: 웹에서 인스타그램 피드·스토리로 바로 올리는 공식 방법은 없다 [조사 §1, 공식 문서 확인 못 함 → **[확인 필요]**]. 그래서 "카드 이미지를 만들어 주고, 사용자가 인스타 앱에서 올린다"가 기본이다.

1. 시트에서 "인스타그램" 선택 → **카드 모달** 열림. 카드 미리보기를 크게 보여 주고 비율 선택: `피드 4:5(1080×1350)` / `스토리 9:16(1080×1920)` [비율·픽셀은 Instagram 도움말 기준 **[확인 필요]**].
2. 카드 이미지는 서버에서 만든 PNG를 받는다(OG와 같은 satori 계열 파이프라인, 크기만 다름 — 설계서 §4.7 ③). 브라우저 캔버스로 직접 그리면 한글 글꼴·외부 이미지(R2) CORS 문제가 생긴다 [제안].
3. 모달 버튼:
   - **[이미지 저장]**: 파일 다운로드. iOS에서는 `다운로드`가 사진 앱이 아니라 파일 앱으로 가는 경우가 있어 **[확인 필요]**, 이때 안내문 "이미지를 길게 눌러 '사진에 추가'를 선택하세요"를 함께 보여 준다.
   - **[이미지로 공유]**(`canShare({files})` true일 때만): `navigator.share({files:[png], text})` → 시스템 공유 시트에서 인스타그램 선택. 지원 여부는 기기·앱 버전에 좌우 [조사 §1].
   - **[문구 복사]**: 사용자가 캡션에 붙일 문구(예: `1997년 11월의 추억 #추억타임머신 #1997 …`) 복사. 해시태그는 [제안] 고정 몇 개 + 연도 1개.
   - **[링크 복사]**: 스토리 링크 스티커용 안내 "스토리의 링크 스티커에 붙여 넣으세요" — 링크 스티커 사용 조건·피드 캡션 링크 비활성 여부는 **[확인 필요]**.
4. 중요한 실행 순서 제약: 공유 시트(`navigator.share`)는 **클릭 직후**에만 열 수 있다(일시적 사용자 활성화, MDN). 이미지 생성이 늦으면 활성화가 만료되어 실패할 수 있다 [브라우저별 지속 시간 **[확인 필요]**]. 해결: 모달이 열릴 때 PNG를 **미리 받아 Blob으로 들고 있다가** 버튼 클릭 시 즉시 `share`에 넘긴다. 클릭 후에 서버에 이미지를 요청하지 않는다.
5. 데스크톱: "이미지 저장"과 "링크 복사"만 활성. "이미지로 공유"는 숨김.
6. 개인정보: 카드에는 닉네임·프로필·사용자 사진이 없다(§1.5). 모달에 "카드에 닉네임 넣기" 토글을 둘 수 있으나 **기본 꺼짐**이고, 글 작성자 본인에게만 보인다 [제안].

### 1.5 공유 카드(이미지) 내용 규칙

| 카드 요소 | 연·월 | 아이템 | 커뮤니티 글 |
|---|---|---|---|
| 제목 | 연월 크게 | 아이템 이름 | 글 제목(없으면 본문 첫 줄) |
| 부제 | 시대 테마 이름 | 카테고리 · 연월(정확도 표기) | 연월 · 카테고리 |
| 본문 | 대표 아이템 3개 제목 | 한 줄 설명 | 본문 발췌 약 100자 |
| 이미지 | 없음(행성 그래픽) | **조건부**: `rights_status`가 재배포·표시 가능(공공누리 1유형, CC, 직접 제작, AI 재현)이고 크레딧 줄을 넣을 수 있을 때만. 아니면 텍스트 카드 + "출처 링크" 문구 | 기본 없음. 작성자가 "내 사진을 카드에 쓰기"를 켠 경우만, 얼굴 경고 문구 확인 후 |
| 배지 | — | `AI 사료 복원`(해당 시 필수, 이미지 안에 직접 표시) | — |
| 출처 줄 | — | 출처 이름(기관/사이트), CC·공공누리 크레딧 | — |
| 푸터 | 사이트명 + 도메인 | 동일 | 동일 |
| 금지 | 닉네임, 실명, 연락처, 얼굴 사진 자동 삽입, 로그인 필요 글의 내용 | 저작권 있는 이미지(썸네일 판례가 2006년 1건뿐 → 링크+설명이 안전, §5.3-1) | 비공개·신고 숨김 글 내용 |

이미지 라이선스별 표기 문구(CC BY-SA 등 크레딧 형식)는 **[확인 필요]**: 아이템 데이터의 `credit` 필드(§10.3 ITEM_IMAGES)를 카드에 그대로 찍는 방식 [제안].

### 1.6 카카오 공유 조건

사전 조건(조사 §1·§3, Kakao Developers `kakaotalk-share/js-link` 문서 기준):
1. 카카오 앱 생성 → **JavaScript 키** 발급. JS SDK 도메인에 사이트 도메인 등록(운영·미리보기 도메인 각각). 도메인 미등록이면 공유가 실패한다 [확인].
2. SDK 모듈명은 1.43.0부터 `Kakao.Share` [확인]. 페이지당 1회 `Kakao.init(키)` 후 `isInitialized()` 확인.
3. 로그인용 카카오 앱과 같은 앱을 쓸 수 있는지(확정 Q8-1: 로그인은 카카오·구글)는 **[확인 필요]**. 같은 앱이면 키·도메인 관리가 한 곳이다 [제안].
4. 무료 쿼터 수치는 콘솔 [쿼터] 메뉴에서 확인(공개 수치 [미확인]). 로그인 없이 공유가 되는지도 **[확인 필요]**.

방식 [제안]: **`sendDefault`(피드 템플릿)를 기본**으로 한다. 제목·설명·이미지·링크를 코드에서 직접 지정하므로 연도·월·AI 배지 문구를 통제할 수 있다. `sendScrap`은 페이지 OG를 긁어 오므로 OG 캐시 문제를 그대로 물려받는다.

| 필드 | 값 |
|---|---|
| title | OG 제목과 동일(§2 규칙) |
| description | OG 설명과 동일(최대 길이는 **[확인 필요]**, 한글 기준 80자 이내 권장 [제안]) |
| imageUrl | `og:image`와 같은 URL(버전 값 포함). 공개 HTTPS 절대 URL, 5MB 이하 [확인: 업로드 이미지 기준, 외부 URL 규격은 **[확인 필요]**] |
| link.webUrl / mobileWebUrl | 카노니컬 URL + `utm_source=kakao&utm_medium=share` |
| buttons | `[{title:'추억 보러 가기', link:{…같은 URL}}]` |

공유 가능 조건(이 사이트 규칙) [제안]:
- 공개 상태이고 신고 숨김이 아닌 페이지만. 아니면 카카오 칸을 숨긴다.
- 로그인해야 보이는 글이라면 카드에 내용 발췌를 넣지 않고 일반 문구만.
- 이미지는 §1.5 조건을 충족하는 카드 PNG만. 저작권 있는 외부 이미지를 `imageUrl`로 직접 넘기지 않는다.
- 카카오가 이미지·메타를 캐시한다 → 같은 URL이 갱신되지 않는다. **이미지 URL의 `v` 값이 바뀌어야** 새 카드가 나간다(§2.3). 카카오 서버에 올라간 이미지는 최대 100일 보관 [확인] → 삭제 후에도 이미 보낸 카드는 남는다는 안내를 개인정보 처리방침과 공유 시트 하단에 둔다(§2.4).
- 카카오톡 PC 환경의 동작(팝업·로그인 요구 여부)은 **[확인 필요]**.

## 2. 메타태그 템플릿

### 2.1 공통 규칙
- 모든 공유 대상 페이지는 **서버가 내려주는 첫 HTML에 메타태그가 들어 있어야 한다.** 카카오·페이스북·X 크롤러는 JS를 실행하지 않는다고 가정한다(조사 §4, 크롤러별 실행 여부는 공식 확인 못 함 → 안전하게 "실행 안 함").
  - 연·월·아이템: 빌드 시 프리렌더(경로가 정해져 있음). 커뮤니티 글: Cloudflare Pages Functions + HTMLRewriter로 `<head>`만 치환(§4.7 ③, §10.2).
- 모든 URL은 **절대 URL + HTTPS**. `og:url`과 `<link rel="canonical">`은 UTM·세션 파라미터 없는 깨끗한 주소.
- 길이 [제안]: 제목 한글 30자 안팎, 설명 80자 안팎(플랫폼별 잘림 기준 **[확인 필요]**). 이모지는 메타에 쓰지 않는다.
- 사용자 입력(글 제목·본문)은 HTML 이스케이프하고, URL·전화번호·이메일 패턴은 발췌에서 제거한다.
- 아래 `{…}`는 데이터 필드 자리이고 예시 값은 형식 설명용이다.

### 2.2 페이지 종류별 규칙표

| 태그 | 홈 `/` | 연도 `/1997` | 월 `/1997/11` | 아이템 `/item/<id>` | 글 `/post/<id>` (공개) |
|---|---|---|---|---|---|
| `og:type` | website | website | website | article | article |
| `og:site_name` | 추억 타임머신 | 동일 | 동일 | 동일 | 동일 |
| `og:locale` | ko_KR | 동일 | 동일 | 동일 | 동일 |
| `og:title` | `추억 타임머신 — 연도·월별 한국 추억 여행` | `{YYYY}년의 추억 — 추억 타임머신` | `{YYYY}년 {M}월의 추억 — 추억 타임머신` | `{제목} ({연월표기}) — 추억 타임머신` · AI이면 앞에 `[AI 재현] ` | `{글 제목} — {YYYY}년 {M}월의 추억` (월 모르면 `{YYYY}년의 추억`) |
| `og:description` | 연도는 행성, 월은 위성. 그 시절 유행을 구경하고 추억을 나눠요. | `{대표1}, {대표2}, {대표3} … {YYYY}년을 기억하나요? 월별로 둘러보고 내 추억도 남겨요.` | `{대표1}, {대표2}, {대표3} … {YYYY}년 {M}월 그때 그 시절. 지금 {N}개의 추억이 모였어요.` | `{한 줄 설명}` + ` · 출처: {출처 이름}`. AI이면 `AI로 다시 그린 재현 이미지예요.` 추가 | `{본문 발췌 약 100자}` (링크·연락처 제거, 닉네임 없음) |
| `og:image` | `/og/site.png?v={templateVer}` | `/og/year/{YYYY}.png?v={hash}` | `/og/month/{YYYY}-{MM}.png?v={hash}` | `/og/item/{id}.png?v={hash}` | `/og/post/{id}.png?v={hash}` |
| `og:image:width/height` | 1200 / 630 | 동일 | 동일 | 동일 | 동일 |
| `og:image:alt` | 사이트 소개 한 줄 | `{YYYY}년 {테마 이름} 카드` | `{YYYY}년 {M}월 카드` | `{제목} 카드` (AI이면 `AI 재현 이미지` 포함) | `{글 제목} 카드` |
| `og:url` | `https://{도메인}/` | `https://{도메인}/{YYYY}` | `https://{도메인}/{YYYY}/{MM}` | `https://{도메인}/item/{id}` | `https://{도메인}/post/{id}` |
| `twitter:card` | summary_large_image | 동일 | 동일 | 동일 | 동일 |
| `twitter:title/description/image/image:alt` | OG 값과 동일 | 동일 | 동일 | 동일 | 동일 |
| `canonical` | `og:url`과 동일 | 동일 | 동일 | 동일 | 동일 |
| `robots` | index | 콘텐츠 N건 미만이면 noindex [제안] | 동일 | 동일 | index (숨김 상태는 §2.4) |
| 추가 | — | — | — | `article:published_time` 불필요 | `article:published_time`(작성 시각), `article:section`(카테고리) |

값 정의:
- `{연월표기}`: 시기 정확도(§5.5)를 반영 — 정확한 월 `1997.11` / 연도만 `1997` / 대략 `1950년대 초`. 월을 모르는데 억지로 월을 쓰지 않는다.
- `{대표1~3}`: 해당 연·월의 검토 완료(`review_status`) 아이템 중 우선순위 상위 3개 제목만. 검토 전 아이템은 쓰지 않는다. 3개가 안 되면 있는 만큼만, 0개면 `{YYYY}년 {M}월에는 어떤 일이 있었을까요? 곧 채워져요.` 같은 일반 문구 + noindex.
- `{N}`: 공개된 글 수. 0이면 문장 생략.
- `{templateVer}`/`{hash}`: §2.3.
- 도메인은 아직 정해지지 않았다 — 웹미리보기의 `chueok-timemachine.kr`은 임시 문구로 보고 **[미정]**.

### 2.3 og:image 버전 값 규칙
- 형식: `?v={8자리 해시}`. 해시 입력 = `카드 템플릿 버전 + 제목 + 설명 + 카드에 들어가는 이미지 ID + AI 여부 + 닉네임 표시 여부`. 시각(타임스탬프)만으로 버전을 만들지 않는다(안 바뀌었는데 매번 새 이미지로 인식됨).
- 내용이 바뀌면 값이 바뀌고, 카드 디자인을 바꾸면 `templateVer`를 올려 전체 값이 바뀐다.
- 이유: 카카오는 같은 경로의 이미지를 캐시 초기화하지 않을 수 있어 **이미지 URL을 바꾸는 것이 확실**하다(조사 §3, 커뮤니티 답변 기반 → **[확인 필요]**). 페이스북은 Sharing Debugger로 갱신, 카카오는 공유 디버거로 캐시 초기화 가능(조사 §3).
- 서버 이미지 응답 헤더: `Cache-Control: public, max-age=31536000, immutable`(URL이 바뀌므로 안전) [제안; §10.4의 엣지 캐시 30일과 조율 **[미정]**].
- 이미지는 R2 `og/…` 경로에 저장(§10.4). 아이템·글 삭제 시 R2 파일도 삭제.

### 2.4 비공개·삭제·신고 숨김일 때
| 상태 | HTTP | 메타 | 비고 |
|---|---|---|---|
| 정상 공개 | 200 | §2.2 | |
| 신고 3건 누적 자동 비공개(AC-07) / 작성자 비공개 | 200 | `og:title`=`추억 타임머신`, `og:description`=`비공개된 글이에요`, `og:image`=`/og/site.png?v=…`, `robots: noindex` | 글 제목·본문·카드 이미지 노출 금지. 공유 버튼은 화면에서 숨김 |
| 삭제 | 410(또는 404) | 일반 문구 + noindex | 크롤러가 HTML을 안 읽을 수 있음 → 링크만 표시되는 것이 정상 |
| 로그인 필요 글(정책이 생길 경우) | 200 | 일반 문구, 내용 발췌 금지 | 글 공개 정책 **[미정]** |
- 이미 카카오·페이스북 등에 캐시된 미리보기는 즉시 사라지지 않는다. 카카오 서버 업로드 이미지는 최대 100일 보관 [확인] → 공유 시트 하단과 개인정보 처리방침에 "공유한 미리보기는 외부 서비스에 남을 수 있어요"를 적는다(조사 §6).
- 아이템이 `review_status` 반려·권리 문제(`rights_status`)로 내려가면 같은 방식으로 일반 문구로 바꾸고 이미지 R2 파일 삭제.

### 2.5 구현 확인 필요 항목 (메타태그 관련)
- Cloudflare 봇 방어(Bot Fight Mode·WAF 규칙)가 카카오·페이스북·X 크롤러를 막는지 **[확인 필요]**. `robots.txt`와 방화벽에서 각 크롤러 접근 허용을 실제 공유로 테스트.
- HTMLRewriter로 글 메타를 넣을 때 D1 조회가 요청마다 생긴다 → 캐시(KV/Cache API, 짧은 TTL)와 삭제·비공개 즉시 반영의 균형 **[확인 필요: Functions 사용량·무료 한도]**.
- `og:image` 1200×630 권장은 페이스북 가이드 기준 일반론 [조사 §3, **[확인 필요]**]. 카카오 피드 이미지 권장 비율·최소 크기도 카카오 문서로 확인.
- X가 `twitter:*` 없이 OG만으로 카드를 만드는지(조사: 없으면 OG로 대체) **[확인 필요]** — 태그는 어차피 같이 넣는다.
- 한글 글꼴 서브셋(Pretendard) 포함 시 라이선스 조건 **[확인 필요]**.

### 3.2 빠진 것

**공유**
- 연도·월·아이템·글 어디에도 **공유 버튼이 없다**(화면 3 하단 `광고 자리 · 후원`만). §1.2 위치대로 추가하고, 공유 시트·인스타 카드 모달·"링크를 복사했어요" 토스트·카카오 실패 상태 화면을 새로 그려야 한다.
- 공유 카드(OG 이미지) 시안이 없다. 연·월·아이템(실제 이미지형 / 텍스트형 / AI형)·글 4~5종 시안이 필요하다.

**접근성·모션**
- **모션 줄이기 토글**이 없다. `prefers-reduced-motion` 자동 반영 + 사이트 내 토글(§4.3, WCAG 2.2 SC 2.3.3)과 "건너뛰기"를 분리해서 그려야 한다. 현재 "연출 끄기" 하나.
- 저사양·WebGL 불가 시 CSS 전환 대안 화면 없음.
- 3D 월 위성이 **키보드로 접근 가능한 버튼**인지, 3D를 못 쓰는 사용자용 텍스트 목록(1~12월 링크)이 있는지 표현 없음.
- 폰트 최소 크기: `.badge` 10px, `.card small`·`.lbl`·`.moon` 11px, `.years` 12px는 너무 작다(설계에 최소 크기 규정은 없으나 AC-06의 가독·44px 취지에 반함). 이모지가 정보 전달 수단으로 쓰이는 곳(탭·카테고리·반응)에는 글자 라벨이 필요.
- 포커스 표시·`aria-label`·제목 계층(h1~)·`<main>`·건너뛰기 링크 등 마크업 요소 없음(정적 목업이라 당장은 정상이나 구현 체크리스트로 이월).

**출처·AI 배지 규칙** (§5.5, AC-08)
- 카드·상세에 필요한 것: **출처 이름 + 링크**, 권리 상태 표시(공공누리·CC·직접 제작·링크만), **시기 정확도 라벨**(정확한 월 / 연도만 / 대략), 검토 상태, "수정 제보" 진입점.
- AI 배지: 상세에만 있다. **카드(목록)·공유 카드·검색 결과**에도 있어야 하고, 카드 이미지 안에 직접 박혀야 한다(복사·캡처되어도 따라가게). 배지 색(`#6b3fd1`)이 일반 `badge`와 구분되는 점은 좋다.
- "AI 사료 복원"은 이미지가 실제 사진이 아님을 알리는 라벨이다. `확인 안 된 부분` 문구가 있는 점은 AC-08에 부합. 다만 **참고 사료가 링크가 아니라 글**이다 → 링크 필수.
- AI 생성물 표시 의무(AI 기본법, 2026-01-22 시행)의 적용 방식 **[확인 필요]**. 설계서도 미확인 상태.

**기타 누락 화면·요소**
- 로그인(카카오·구글, Q8-1), 글쓰기, 댓글 영역, **신고 버튼**, 반응 버튼의 실제 상태(눌림/취소, AC-05).
- 검색 결과·빈 상태(AC-02), "준비 중" 연도(§4.1 열림/준비 중), 404·삭제된 글.
- 개인정보 처리방침·소개 링크(AdSense 신청 준비물, §11) 푸터.
- 사용자 제보("이 아이템 추가해 주세요", Q5-1) 진입점. 상세에는 오류 수정 제보만 있다.
- 댓글 작성자·글 작성자 **닉네임을 화면에서 보여 줄지**가 설계서에 정의가 없다. 공유 카드 기본 비노출과 별개로 **페이지 안 노출 정책 [미정]**.
- 첫 방문 길잡이(출생연도·"기억하는 해" 선택)가 `🔍 검색 · 내 출생연도로 가기` 한 칩에 뭉쳐 있다. 검색과 출생연도 입력은 다른 동작이므로 분리 필요.
- 광고(애드센스) 자리: 광고 라벨, 공유·CTA 버튼과의 거리(실수 클릭 유발 배치 금지 — 정책 문구 **[확인 필요]**), 3D 화면 위 광고 금지, 레이아웃 흔들림 방지 높이 확보. 설계서 §11이 말한 "글이 충분한 일반 HTML 페이지"가 어떤 모습인지도 안 그려져 있다.

### 3.3 실제 구현 시 주의점

1. **공유는 첫 HTML 기준**: 3D/SPA가 `document.head`를 바꾸는 방식은 크롤러에 안 보인다(§2.1). 연·월·아이템은 프리렌더, 글은 HTMLRewriter.
2. **클릭 안에서 즉시 공유**: 이미지 파일 공유는 미리 받아 둔 Blob으로(§1.4-4). 비동기 생성 뒤에 `navigator.share`를 부르면 실패할 수 있다.
3. **공유 취소는 오류가 아니다**: `AbortError`는 조용히 무시.
4. **iOS 이미지 저장**: 다운로드가 사진 앱으로 안 가는 경우의 안내 문구 준비 **[확인 필요: 실기기]**.
5. **인앱 브라우저**(카카오톡·인스타·네이버)에서 공유·클립보드·다운로드 동작이 달라진다 → 실기기 테스트 항목으로 등록 **[확인 필요]**.
6. **카카오 캐시**: 이미지 URL 버전 값(§2.3). 도메인 등록(운영·미리보기 도메인 별도). 키는 공개 JS 키만 클라이언트에, 시크릿 키는 절대 넣지 않는다.
7. **크롤러 허용**: Cloudflare 봇 방어·robots.txt·로그인 벽이 카카오·페이스북·X 크롤러를 막지 않는지 실제 공유로 확인.
8. **개인정보**: 닉네임·아바타·사용자 사진·이메일이 공유 카드·메타 설명에 자동으로 들어가지 않게 템플릿 필드를 화이트리스트로 만든다(제목·발췌·연월·카테고리만). 사용자 입력은 이스케이프, 링크·연락처 패턴은 발췌에서 제거.
9. **데이터 모델 보완**(§10.3): 공유를 위해 아래 필드가 필요하다 [제안].
   - POSTS: `visibility`(공개/비공개/신고숨김), `card_show_nickname`(기본 false), `card_use_photo`(기본 false), `og_hash`.
   - ITEMS: `og_hash`, 카드용 이미지 사용 가능 여부(권리 상태에서 파생해도 됨), 슬러그 규칙.
   - POSTS의 월 null 허용 → 카드·메타·URL이 연도만 있는 글을 처리하도록 규칙 필요(`/post/<id>`는 월과 무관).
10. **3D 접근성**: 월 선택은 3D 클릭에만 의존하지 말고 같은 정보를 담은 일반 HTML 월 목록(링크)을 항상 제공(검색 노출·키보드·저사양 대안·AdSense 콘텐츠 요건 모두 해결, §11).
11. **카드 비율**: 설계서는 4:3 카드인데 미리보기 `.pic`은 약 3.3:1(높이 90px)로 훨씬 납작하다. 실제 이미지 비율 기준 검토.
12. **외부 CDN 의존**: 미리보기는 jsDelivr의 Pretendard를 쓴다. 운영에서는 글꼴 서브셋을 직접 호스팅(성능, 공유 카드 생성용 글꼴 파일과 공용) [제안; 라이선스 **[확인 필요]**].
13. **광고 정책과 공유 UI 충돌 방지**: 광고를 공유 시트·모달·카드 목록 안에 끼우지 않는다. 애드센스는 이미지·영상 위주 페이지 승인이 어려울 수 있다는 안내가 있으므로(설계서 §11) 공유 카드가 가득한 갤러리 페이지에 텍스트가 충분한지 별도 점검.
14. **AC 보강**: 공유용 인수 조건을 §8에 추가할 것을 제안한다 [제안]:
    - AC-09 공유 미리보기: `/1997/11` 링크를 카카오톡에 보내면 제목·이미지가 §2.2대로 보인다(JS 비실행 환경에서).
    - AC-10 개인정보: 공유 카드·메타 설명에 닉네임·사용자 사진이 없다(옵션을 켠 경우 제외).
    - AC-11 AI 표시: AI 아이템을 공유한 카드·설명에 AI 표시가 있다.
    - AC-12 비공개: 비공개·삭제 글 링크의 미리보기에 글 내용이 없다.
